# Helm Deploy Defaults Implementation Plan (issue #117)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a fresh `helm install` self-sufficient (chart renders the static `agent-kubeconfig` Secret) and default the operator identity to a single `admin` across chart, backend config, web, and e2e.

**Architecture:** Two independent, non-code-runtime changes. Part 1 adds a Helm `Secret` template and removes the out-of-band creation step in `scripts/setup.sh`. Part 2 changes default identity values that currently hardcode `zhang.wei` / `zhang.wei,li.ming`. No controller/gateway logic changes.

**Tech Stack:** Helm v3 chart (values/templates), Bash (`scripts/`), Go (`internal/config`), TypeScript (`web/`), Ginkgo e2e harness.

## Global Constraints

- Work only inside the worktree: `cd /home/zhujian/code/github.com/suanova/cubepilot/.claude/worktrees/fix-issue117-agent-kubeconfig-chart`

- Secret name is fixed in Go (`internal/k8s` `KubeconfigSecretName = "agent-kubeconfig"`); keep the rendered name exactly `agent-kubeconfig`. Keep it a `kind: Secret` (the controller reads it via a `corev1.Secret` Get), never a ConfigMap.
- No values toggle: the chart always renders the Secret.

- [ ] **Step 1: Create the Secret template**

Create `deploy/charts/cubepilot/templates/agent-kubeconfig.yaml`:

```yaml
{{- /*
agent-kubeconfig -- static in-cluster kubeconfig for the platform
(cubepilot-agent SA) identity (issue #117). Rendered by the chart: it is a
fixed, non-sensitive in-cluster kubeconfig (in-cluster API server + the
agent Pod's own mounted ServiceAccount), identical on every cluster, that the
AgentInstance controller requires before provisioning any agent Pod
(internal/k8s KubeconfigSecretName). The chart dir is the single source of
truth for this content (an OCI-packaged chart cannot read files outside its
own dir via .Files).
*/ -}}
apiVersion: v1
kind: Secret
metadata:
  name: agent-kubeconfig
  namespace: {{ .Release.Namespace }}
  labels:
    {{- include "cubepilot.labels" . | nindent 4 }}
type: Opaque
stringData:
  # Dual-kubeconfig (issue #19): mounted on the agent Pod's NON-default path
  # $CUBEPILOT_PLATFORM_KUBECONFIG and used only for CRD/kind schema
  # discovery; user-facing kubectl runs with the user's own kubeconfig.
  config: |
    apiVersion: v1
    kind: Config
    clusters:
      - cluster:
          certificate-authority: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt
          server: https://kubernetes.default.svc
        name: in-cluster
    contexts:
      - context:
          cluster: in-cluster
          user: agent
        name: in-cluster
    current-context: in-cluster
    users:
      - name: agent
        user:
          tokenFile: /var/run/secrets/kubernetes.io/serviceaccount/token
```
