# Design: zero-local-dependency `scripts/setup.sh`

Date: 2026-08-25
Status: approved (user: "ok")
Goal owner: zhujian

## 1. Context & goal

Today `scripts/setup.sh` reaches into the host machine to bring up the CubePilot
stack on a kind cluster:

1. It reads `~/.openclaw/openclaw.json` (overridable via `OPENCLAW_HOST_CONFIG`)
   and extracts an allowlist (`models.providers`, `agents.defaults.*`,
   `gateway.*`, `gateway.auth.token`) into the in-cluster `openclaw-config`
   Secret.
2. It depends on a **locally pre-built** `openclaw:local` image (the agent
   runtime image and the operator/api images all `FROM openclaw:local`).
3. It builds the two Go binaries (`cubepilot-operator`, `cubepilot-api`) on the
   **host** (`go build`), and (latently) requires a host-built
   `bin/cubepilot-supervisor` that no script actually builds — the openclaw
   agent image `COPY`s it, so the current script fails at that `docker build`
   unless the binary was produced by hand.

The end goal is **running CubePilot end-to-end on CI**. Therefore setup.sh must
depend on **no machine-local state**: no host config file, no pre-built local
images, no host Go toolchain. The only user-supplied input is the LLM provider
credentials, passed as an environment variable (a CI secret in CI).

## 2. Requirements

- R1. `scripts/setup.sh` must not read `~/.openclaw/*` or any other host config
  path.
- R2. All images build self-contained inside Docker (multi-stage). No host
  `go build`, no host-built `bin/` artifacts, no pre-built `openclaw:local`.
- R3. All credentials the service needs are either (a) supplied by the caller
  via env/flag at setup time, or (b) generated by setup.sh itself (gateway
  token). Nothing is pulled from a user profile.
- R4. The script runs on a clean machine / fresh CI runner that has only
  docker, kind, kubectl, helm, jq (and creates the kind cluster itself if
  missing).
- R5. Fix the latent supervisor-binary break (R2 subsumes this).
- R6. CRDs come from a single source: the Helm chart's `crds/` (installed by
  `helm install`). The redundant `kubectl apply -f config/crd/bases/` (which
  today also applies two deleted CRDs, `agents.yaml` and `models.yaml`) is
  removed.

### Non-goals

- Removing the CLI-toolchain prerequisites (docker/kind/kubectl/helm/jq) — they
  are inherent to a kind-cluster deployment and available on standard CI
  runners. Changing deployment target is out of scope.
- Deleting `config/crd/bases/agents.yaml` / `config/crd/bases/models.yaml` —
  flagged as a follow-up; R6 only stops setup.sh from applying them.

## 3. User-supplied inputs

All inputs are environment variables; flags are accepted as equivalents and
documented in `--help`.

| Env var / flag | Required | Default | Purpose |
|---|---|---|---|
| `CUBEPILOT_MODEL_PROVIDERS` / `--providers-json` | **yes** | — | The `models.providers` object verbatim, e.g. `{"deepseek":{"api":"sk-...","baseUrl":"https://api.deepseek.com","models":[{...}]}}`. One provider is enough for testing. |
| `CUBEPILOT_DEFAULT_MODEL` / `--default-model` | no | first provider's first model id | `agents.defaults.model.primary`, e.g. `deepseek/deepseek-v4-flash`. |
| `CUBEPILOT_GATEWAY_TOKEN` / `--gateway-token` | no | `openssl rand -hex 32` | Shared gateway auth token; injected into the `openclaw-config` Secret as `gatewayToken` and into `openclaw.json`'s `gateway.auth.token`. Caller never needs to know it. |
| `CUBEPILOT_KIND_CLUSTER` | no | `cube` | Kind cluster name (existing). |
| `CUBEPILOT_NAMESPACE` | no | `cubepilot` | Target namespace (existing). |
| `CUBEPILOT_SKIP_CLUSTER_CREATE` | no | unset | If set (any non-empty value), do not `kind create cluster`. |
| `CUBEPILOT_KIND_CONFIG` | no | default (single-node) | Path to a `kind` config file for cluster creation. |

Validation: `CUBEPILOT_MODEL_PROVIDERS` is required and must parse as valid JSON
with at least one provider and one model; otherwise exit with a clear message.

## 4. In-cluster `openclaw.json` construction

The allowlist config is built with `jq` from the user-supplied providers plus
fixed defaults (no host source). Deriving the agent model catalog and default
primary:

```jq
.providers = ($providers | fromjson) |                      # CUBEPILOT_MODEL_PROVIDERS
.modelCatalog = [                                           # {"<p>/<id>": {alias: <name>}}
  .providers | to_entries[] as $p |
    (($p.value.models // []) | map({ key: "\($p.key)/\(.id)", value: { alias: (.name // .id) } }))
] | add |
.defaultModel = (($defaultModel // "") | if . != "" then . else
  (.providers | to_entries[0] | "\(.key)/\(.value.models[0].id)")
end)
```

The resulting object (same shape the current allowlist produces, minus
host-derived fields):

```json
{
  "models": { "providers": <user-supplied> },
  "agents": {
    "defaults": {
      "workspace": "/home/node/.openclaw/workspace",
      "model": { "primary": <defaultModel> },
      "models": <derived catalog>,
      "sandbox": { "mode": "off" }
    }
  },
  "gateway": {
    "mode": "local",
    "port": 18789,
    "bind": "lan",
    "http": { "endpoints": { "chatCompletions": { "enabled": true } } }
  },
  "tools": {
    "exec": { "security": "full", "ask": "off" },
    "sessions": { "visibility": "all" }
  }
}
```

Notes:
- `gateway.auth.token` is added with the (auto-)generated token so config and
  env agree with the `gatewayToken` Secret key (`OPENCLAW_GATEWAY_TOKEN` is
  injected separately by the supervisor pod template).
- `memorySearch` / `controlUi` are dropped; they were host-derived and have
  safe openclaw defaults when absent.
- The `openclaw-config` Secret keeps two keys: `openclaw.json` and
  `gatewayToken` (unchanged consumer contract; `internal/k8s/resources.go` and
  the chart `_helpers.tpl` are untouched).

## 5. Image strategy (all self-contained Docker multi-stage)

| Image | Before | After |
|---|---|---|
| `cubepilot-openclaw` (agent runtime) | `FROM openclaw:local` + COPY host-built supervisor | `FROM ghcr.io/openclaw/openclaw:2026.6.33` + a `golang:1.26` stage that builds `cubepilot-supervisor` (`CGO_ENABLED=0 go build ./cmd/cubepilot-supervisor`), COPY it in, install kubectl, seed `workspace/` (all existing steps unchanged) |
| `cubepilot-operator` | `FROM openclaw:local` + COPY host-built binary | `golang:1.26-bookworm` build stage → `node:24-bookworm-slim` runtime (user `node`, ENTRYPOINT) |
| `cubepilot-api` | same as operator | same pattern as operator |
| `cubepilot-web` | node→nginx multi-stage | unchanged |

- Pin the openclaw base to the exact release tag `2026.6.33` (matches the
  checked-out openclaw repo version). Implementation must verify the tag exists
  on ghcr (`ghcr.io/openclaw/openclaw`); fall back to the tag documented by
  `docs/install/docker.md` if 2026.6.33 is not published. Never `:latest`.
- `go 1.26.0` in `go.mod` → `golang:1.26` build images.
- `bin/` host builds and `Makefile build/images` remain only as a convenience
  for developers; `scripts/setup.sh` stops invoking them.

## 6. Kind cluster bootstrap

After tool checks, setup.sh ensures a cluster exists:

```bash
if ! kind get clusters | grep -qx "$KIND_CLUSTER"; then
  if [ -n "$CUBEPILOT_SKIP_CLUSTER_CREATE" ]; then
    echo "kind cluster '$KIND_CLUSTER' missing; CUBEPILOT_SKIP_CLUSTER_CREATE is set"; exit 1
  fi
  kind create cluster --name "$KIND_CLUSTER" ${CUBEPILOT_KIND_CONFIG:+--config "$CUBEPILOT_KIND_CONFIG"}
fi
```

Then proceeds as today: build images → `kind load docker-image` → namespace/RBAC
→ Secrets → `helm upgrade --install`.

## 7. Secrets (unchanged consumer contract)

1. `agent-kubeconfig` — from `deploy/agent-kubeconfig.yaml` (unchanged).
2. `openclaw-config` — `openclaw.json` (built in §4) + `gatewayToken`
   (auto-generated, or caller-supplied).

## 8. CRD handling

- Remove the `kubectl apply -f "$REPO_DIR/config/crd/bases/"` step; CRDs ship
  in the chart's `crds/` and install with `helm install`.
- Follow-up (not in this change): delete stale `config/crd/bases/agents.yaml`
  and `config/crd/bases/models.yaml`.

## 9. Files touched

- `scripts/setup.sh` — main rewrite (inputs, jq, cluster bootstrap, drop CRD apply, drop host builds).
- `deploy/openclaw-image.Dockerfile` — self-contained (supervisor build stage, ghcr base).
- `deploy/operator-image.Dockerfile` — golang multi-stage.
- `deploy/api-image.Dockerfile` — golang multi-stage.
- `README.md` — prerequisites (drop `openclaw:local`; document `CUBEPILOT_MODEL_PROVIDERS` and CI usage).
- `Makefile` — optional: keep host `build`/`images` for dev convenience; no behavioral change required by setup.sh.

## 10. Verification

- `helm lint` / `helm template` still pass.
- On a clean checkout with no `~/.openclaw`, no `openclaw:local` image, empty
  `bin/`:
  - `CUBEPILOT_MODEL_PROVIDERS='<one provider>' scripts/setup.sh` brings up the
    cluster + deploy.
  - Portal reachable via port-forward; chat smoke test hits the real gateway
    (requires a live API key).
- CI (follow-up): a workflow step provisions kind, runs setup.sh with providers
  from a CI secret, then runs the e2e suite.

## 11. Out of scope / future

- Model credential governance (`Model.credentialRef`, design §3.3) — phase two.
- Stale CRD file deletion (§8 follow-up).
- Pinning the openclaw base by digest (nice-to-have for reproducibility).
