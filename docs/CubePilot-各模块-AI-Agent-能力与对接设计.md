# CubePilot 各模块 AI Agent 能力与对接设计

**状态：** Draft（待评审）　**版本：** v0.1
**定位：** 梳理平台各业务模块（开发环境/数据/模型/训练/评估/推理/镜像/运维/运营/安全）的 AI Agent 能力，并说明各模块如何与 CubePilot 基座对接。基座能力见《CubePilot 功能需求细化文档》，本文档不重复定义基座。

---

# 1. 概述

**定位分工**：CubePilot 是**共享 Agent 基座 + 通用能力**；各业务模块的 AI Agent 能力由**模块自身承接**，通过基座的对接机制暴露给 Agent。

```
用户（UI / 自然语言 / API/CLI 三路径）
        │
        ▼
CubePilot 基座（对话 · 编排 · kubectl 直连 · 报告/告警）
        │  ◄── 能力目录（FR-M3-006）── 各模块登记自己的能力
        ▼
各业务模块能力（开发环境/数据/模型/训练/推理/镜像/运维/运营/安全）
```

# 3. 对接机制（通用 4 步）

各模块 Agent 能力统一按以下方式与基座对接：

1. **能力 API 化**：模块能力遵循 API/CLI-First 原则（平台需求文档 §3），提供标准化 RESTful / OpenAPI / CLI 接口，Agent 可编程调用。
2. **能力目录登记**：模块将能力登记进**能力目录**（FR-M3-006）——每项含用途、关键参数、调用方式、示例；目录随 Agent 上下文注入（FR-M1-005）。
3. **工具化调用**：Agent 依据目录选择能力，经 **kubectl 直连**（FR-M3-001，操作类 CRD）调用；阶段二起复杂操作先 **dry-run 预览**（FR-M3-004），高风险操作需 **HITL 确认**（FR-M3-003）。
4. **凭据与权限继承**：所有调用以用户身份执行（凭据直连 + RBAC），不越权；全程审计（M5）。

**实现归属约定**：
- **基座通用**：问答/编排/记忆/报告/告警 —— CubePilot 提供，各模块复用。
- **能力目录工具化**：模块的**操作类**能力（创建环境、提交训练、部署推理、隔离节点等）—— 模块提供 CRD/API，基座登记为能力/工具。
- **模块自带**：模块的**领域智能**（数据画像、模型推荐、评估解读、成本优化、告警关联等）—— 由模块实现，基座提供对话/推理外壳。

**「模块自带」的实现方式（三种）**：
- **A. 能力 API 化**：模块把领域逻辑封装为 API（如环境诊断：输入环境日志 + GPU/显存指标 → 输出 `{cause, suggestion}`），登记进能力目录（FR-M3-006），基座工具化后 Agent 调用、以自然语言汇报——领域逻辑全在模块代码，Agent 只做翻译与编排。
- **B. 领域 Skill**：模块打包领域技能（查询工具 + 领域提示词），基座在相关场景加载——对应平台文档「各功能模块均内置 AI Agent 能力」。
- **C. 数据开放 + 基座推理**：模块只暴露数据/API，由基座 LLM 直接分析——严格说属于「能力目录工具化」而非「模块自带」；关键诊断场景因纯 LLM 分析可靠性不足，倾向用 A/B。

> **待定（Q-01）**：模块「自带 Agent」的最终形态——独立 Agent 实例，还是复用基座 Agent + 模块注册领域技能（倾向后者，避免每模块一套实例）。
